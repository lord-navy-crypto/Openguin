# Security Toolbox v13 — OWASP/NIST Defense Studio

Security Toolbox v13 adds a bounded, manually controlled **offline defense learning studio** to the real localhost HTTP training site. It is not a network attack generator.

## Sources and mapping

The themes are derived from public authoritative guidance:

- OWASP Web Security Testing Guide (WSTG), identity management, authentication, authorization, input validation and business logic:
  https://owasp.org/projects/web-security-testing-guide
- OWASP Authentication Cheat Sheet, uniform error handling, rate limiting, account lockout and the usability risks of accidental denial of service:
  https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html
- OWASP API Security Top 10 2023, API1 broken object-level authorization, API2 broken authentication, API4 unrestricted resource consumption:
  https://api-security.owasp.org/editions/2023/en/0x11-t10/
- NIST SP 800-63B-4 (2025), authentication and authenticator management, rate limiting of failed attempts:
  https://pages.nist.gov/800-63-4/sp800-63b.html

The studio is a simplified teaching model, not a compliance evaluation, vulnerability scanner, password attack, or real-server capacity test.

## Start

From the v13 OpenPenguin source checkout with Node.js installed:

```sh
npm run security:lab
```

Open **http://127.0.0.1:19090/defense-studio** in the same machine's browser. The Security Lab React UI links to this page. Stop the Node process with Ctrl+C.

The Node server binds only to `127.0.0.1`; it cannot be configured with another host. The v13 modeling engine itself does not send HTTP, socket, or other network traffic at all.

## Manual learning workflow

1. Choose one fixed virtual traffic profile: steady, burst, or recovery.
2. Set the fictional throttle limit to 2, 4, or 6 events per time slot.
3. Set fictional per-slot service capacity to 2, 4, or 6.
4. Select the **protected** or **teaching contrast** policy.
5. Click **Run one offline comparison**. This sends exactly **one local form POST**. Inside the process, pure synchronous code calculates bounded synthetic traffic and authentication/ownership events. The modeled events are not HTTP requests.
6. Observe status counts and the side-by-side comparison:
   - 401 — fictional authentication failure events without any passwords or actual credentials.
   - 403 — denial of another fictional record.
   - 429 — modeled request throttling and rate protection.
   - 503 — modeled capacity exhaustion, with no actual CPU or memory pressure.
7. Change one parameter and repeat, checking whether virtual throttling decreases conceptual unavailability, and how a too-high throttle threshold could allow virtual capacity exhaustion.
8. Export a compact eight-row CSV with counts by time slot.

All counts are deterministic. Modes and thresholds are strictly allowlisted. There are no remote targets, network payloads, custom paths, user accounts, usernames, passwords, hash inputs, exploit attempts, wordlists, CPU stress loops, high-rate traffic generation or automated request sequences.

## Privacy and limitations

- Aggregate-only CSV/JSON excludes target addresses, accounts, cookies, session tokens, CSRF content, request bodies and individual credentials.
- The virtual engine has a fixed eight-slot schedule and fewer than 100 generated in-memory events.
- The real localhost exercise page accepts user actions through a server-issued anti-CSRF token and rejects unsupported configuration values. No target URL or address input exists.
- The model's numbers do not forecast actual network/server throughput or establish real-world attack resistance.
- Existing v9–v12 manual localhost response inspection, protected-vs-education ownership checks, logs, and offline audits remain unchanged.
- No new DMG is generated by this PR. It remains a source-checkout feature; manual macOS browser/desktop QA and a green CI run at the exact commit are prerequisites to merging or packaging.

## Implementation

- `scripts/defense-studio-v13.mjs`: pure bounded models, scenario comparisons, aggregate exports.
- `scripts/localhost-defense-lab.mjs`: UI and same-machine POST/CSV routes.
- `src/LocalhostManualLab.tsx`: direct launch link within the existing Security Lab.
- `tests/defense-studio-v13.test.mjs`: deterministic simulation, bounds, privacy and policy checks.
- `tests/localhost-defense-lab.test.mjs`: real localhost form CSRF, input restrictions and CSV import/export tests.
- `.github/workflows/network-observatory.yml`: Node integration tests, frontend build, native Rust check, extension regression checks.
